\section{Limitations}
\label{sec:limits}

We outline several technical and operational limitations inherent to our approach and evaluation methodology.

\subsection{Run-to-run variance and multi-seed dispersion}

Two runs of the identical configuration under the same random seed, evaluated on an
identical event stream, exhibited minor dispersion (\RunToRunAuc{} in lateral AUC and
\RunToRunRecall{} in lateral recall). While the observed lateral-AUC improvement from the
configuration node (\BlatAucD) exceeds this baseline variation, current benchmark dispersions
(\PublishedSdAuc{} on AUC, \PublishedSdRecall{} on recall) reflect three independent seeds.
Extending evaluations across wider hyperparameter and seed grids remains valuable future work.

\subsection{Synthetic benchmark fidelity}

While synthetic access streams enable controlled parameter variation and multi-seed benchmarking,
synthetic simulations inherently cannot capture the full behavioral heterogeneity of enterprise
networks. To mitigate this risk, our leakage audit (Section~\ref{sec:setup}) enforces invariance
against trivial separability across generator revisions. Furthermore, empirical evaluation on
PicoDomain (Section~\ref{sec:external}) provides qualitative grounding on real enterprise telemetry.

\subsection{Operating recall trade-offs}

While cost-sensitive threshold routing translates ranking discriminability into practical
operating recall, achieving higher detection rates on subtle lateral movement involves an
inherent trade-off with the false-positive rate on benign activity. In production environments,
operators must tune threshold operating points based on organizational risk tolerance and alert
triage capacity.

\subsection{State Complexity and Scalability}
\label{sec:limits-state}

Constant-time tensor lookups and bounded memory consumption apply directly to the GPU/CPU
tensor representations (entity memory vectors, neighbor ring buffers, and static feature tables),
which are allocated at fixed capacity. However, peripheral structures such as interaction frequency
counters and precursor alert trackers scale with the volume of distinct entity pairs. Eviction
mechanisms require buffer scanning for invalidation. While measured serving latency remains within
operational limits ($P_{50} \approx \LatencyPFifty$\,ms, $P_{99} \approx \LatencyPNinetyNine$\,ms),
deployments serving millions of concurrent entities require distributed cache eviction strategies.

\subsection{Commit gate boundary conditions}

Decoupling memory updates via an external policy gate introduces two boundary conditions.
First, if an adversary executes an unauthorized action that satisfies external policy constraints,
the event will be committed to graph memory. Second, if a benign entity undergoes a legitimate
operational change that triggers persistent anomaly flags, its memory updates risk starvation.
In practice, these scenarios require administrative policy review and defined grace periods for
newly provisioned entities.

\subsection{Precursor heuristic scope}

The precursor prior operates on the assumption that lateral movement often follows detectable
reconnaissance activity originating from the same host. While this holds across many enterprise
intrusion patterns, an adversary conducting silent reconnaissance or moving directly from a
pre-established foothold will not trigger the precursor multiplier, leaving detection reliant solely
on graph structural and feature heads.

\subsection{Cold start dynamics}

Newly introduced entities lack sufficient historical interactions for the model to establish
habitual baselines. While evaluation streams allow entities to warm up before measuring lateral
movement, enterprise environments exhibit continuous entity churn. During initial interaction
phases, detection sensitivity is reduced until minimum interaction counts are established.

\subsection{Fingerprint evasion}

The client-configuration node detects unfamiliar client tool stacks associated with known
principals. If a sophisticated adversary faithfully replicates the legitimate user's TLS parameters,
ciphersuite ordering, and client environment, the request appears structurally habitual on the
\textit{config}\,$\rightarrow$\,\textit{user} binding. The configuration node increases adversary
work factor, but does not prevent exact client cloning.

\subsection{Service deployment security}

The serving prototype does not enforce cryptographic mutual TLS or API token authentication
at the transport layer. In production deployments, inference and commit endpoints must be
restricted to internal network fabrics with mutual authentication to prevent unauthorized
state manipulation.
