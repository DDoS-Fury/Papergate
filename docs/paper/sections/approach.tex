A request is not one edge. Modelling it as $u \rightarrow r$ alone --- the
authentication-graph formulation --- discards the question of \emph{how} the principal
arrived. We emit five edges per request (Fig.~\ref{fig:chain}): the four bindings
\textit{source}\,$\rightarrow$\,\textit{config},
\textit{config}\,$\rightarrow$\,\textit{device},
\textit{config}\,$\rightarrow$\,\textit{user} and
\textit{device}\,$\rightarrow$\,\textit{user}, plus the access edge
\textit{user}\,$\rightarrow$\,\textit{resource}. Commit order is fixed and identical in
training, offline replay and serving. When a key is absent the corresponding edge is
skipped and its neighbours bridge: a device-less dataset degrades to
\textit{config}\,$\rightarrow$\,\textit{user}, and a dataset with no client fingerprint
at all --- LANL --- degrades to the legacy \textit{source}\,$\rightarrow$\,\textit{device}
path. The event score is the maximum over the edges present, so a single broken binding
is sufficient to raise it.

The \textit{config} node earns its place on one class. An attacker replaying stolen
credentials issues a request whose principal is habitual, whose resource may well be
habitual, and whose client fingerprint the principal has never used. On the access edge
this is invisible. On the \textit{config}\,$\rightarrow$\,\textit{user} binding it is a
pair with no history.

\subsection{Node embedding}

Fig.~\ref{fig:arch} gives the whole pipeline. Each entity holds a recurrent memory vector,
updated by a GRU from the messages of the events it participates in (memory dimension
256). At scoring time the memory is
concatenated with two further signals. The first is a \textbf{hashed identity}: a
deterministic BLAKE2b hash of the external entity key into a learned embedding table.
Determinism matters --- Python's built-in hash is salted per process and would break
reproducibility across restarts --- and hashing rather than an index table is what keeps
the model fully inductive: an entity never seen at training time gets a coherent
embedding immediately, with no retraining and no vocabulary. The second is a static
attribute vector (device tier, resource sensitivity, network origin, trust score).

The concatenation is passed through a three-hop graph attention encoder over the
entity's recent temporal neighbours, with the edge attribute formed by concatenating a
time encoding of $\Delta t$ with the historical edge message. Neighbours come from a
ring buffer of the last $K{=}30$ temporal neighbours per node, pre-allocated in RAM. The
buffer is the reason no graph database is required.

\subsection{Scoring}

The logit is the sum of two heads. A \textbf{feature head} --- an MLP over both endpoint
embeddings, the current message, the static attributes, recency encodings and history
counters --- carries the policy and contextual classes and the novelty cue for lateral
movement. A \textbf{structural head} --- a scaled cosine similarity between non-linear
projections of the two endpoint embeddings --- is a complementary low-cost signal. The
anomaly score is $1 - \sigma(\text{logit})$.

The history counters deserve a note, because they are where a circularity could hide.
For each edge we compute $[\log(1{+}n_{\text{pair}}), \log(1{+}n_{\text{src}}),
n_{\text{pair}}/(n_{\text{src}}{+}1)]$: how often this exact pair has been seen, how
active the source is, and the ratio. They are \textbf{causal} (only past events) and
\textbf{benign-gated} (incremented only on committed events), so they are derivable at
serving time and cannot leak the label. Every baseline in Section~\ref{sec:results}
receives these same counters --- otherwise the comparison would measure feature
engineering rather than the temporal-relational machinery.

Relative time is capped and carries an explicit ``never seen'' sentinel. Without the
cap, ``never seen before'' was encoded as the absolute clock, which grows along the
stream: training, validation and test saw different encodings of the same state, a
long-lived server drifted, and the contrastive objective had a shortcut, since a random
negative is by construction a pair never seen. One implementation of this is shared by
replay, the training objective and serving.

\subsection{Kill-chain precursor}

Lateral movement typically follows reconnaissance that trips a sensor on the same
origin --- but the commit gate discards precisely that precursor from memory, since the
policy engine denies it. We therefore keep a small per-entity alert state outside the
TGN memory and apply a multiplicative prior with exponential decay to the score of
subsequent events from that entity. It is multiplicative by design: it lifts an already
suspicious score above threshold without turning benign scores near zero into false
positives. It is a serving-time heuristic, not a trained input --- benign-only training
would make it a dead feature --- and an adversary who skips the noisy reconnaissance
evades it.

\subsection{Threshold calibration}

The primary threshold is a quantile of the signal-clean benign score distribution at a
target FPR, computed on a validation replay that uses \emph{the same gate as the test}
and no labels. Calibration runs as a two-pass fixed point with a snapshot/restore of the
runtime state between passes, so the second pass does not observe a memory that has
already ingested its own slice. A cost-sensitive routed threshold, which converts
ranking quality into operating recall at a higher benign FPR, is reported separately;
it needs labelled lateral events in the validation window and is therefore quoted as a
declared upper bound rather than as a deployable default.

\subsection{Serving}

Inference is exposed as an HTTP service. Per request the flow is: map the five keys to
memory slots, admitting unseen entities dynamically; expand temporal neighbourhoods;
embed; score; return the verdict to the orchestrator, which consults the policy engine
and calls back to commit or not. Measured end-to-end latency is
$P_{50} \approx \LatencyPFifty$\,ms and $P_{99} \approx \LatencyPNinetyNine$\,ms
(\prelimnote), each request performing five neighbourhood expansions and five encoder
forward passes.

Offline evaluation does not call the serving primitives; it is a vectorised
re-implementation that scores a block against a start-of-batch memory snapshot. We do
not claim shared code. What binds them is a test: the same stream is replayed
event-by-event through the serving primitives and compared against replay with batch
size one, agreeing to $\max|\Delta| = \ParityDelta$ on both the five-edge chain and the
legacy path. An earlier version of this harness exercised only the legacy branch; the
five-edge chain, i.e. the configuration actually deployed, had never been verified.
